## 1. Tổng quan hệ thống sau SF13

Hệ thống đã chuyển từ trạng thái public tự do (M1) sang **hệ thống có bảo vệ phiên đăng nhập và phân quyền 2 cấp (M2)**:
1. **Chưa đăng nhập (Anonymous):** Không thể đọc hay ghi bất kỳ dữ liệu kho nào (Backend trả HTTP `401 Unauthorized`).
2. **Nhóm `viewer` (Chỉ xem):** Được gọi các API đọc (`GET`), nhưng bị chặn toàn bộ thao tác ghi (`POST`, `PATCH`, `DELETE` trả HTTP `403 Forbidden`).
3. **Nhóm `manager` (Quản lý kho / Bếp trưởng):** Được toàn quyền đọc và ghi (`GET`, `POST`, `PATCH`).
4. **Bảo vệ CSRF:** Toàn bộ request thay đổi dữ liệu (`POST`, `PATCH`, `PUT`, `DELETE`) bắt buộc phải có CSRF token hợp lệ (nếu thiếu hoặc sai sẽ bị chặn HTTP `403 Forbidden`).

## 2. Danh sách API Xác thực đã sẵn sàng

Frontend và các thành viên khác sử dụng 4 API sau tại tiền tố `/api/auth/`:

### 2.1. Lấy CSRF Token
* **URL:** `GET /api/auth/csrf/`
* **Mục đích:** Client gọi trước khi thực hiện bất kỳ request POST nào để nhận cookie `csrftoken` và chuỗi token trong JSON.
* **Response `200 OK`:**
  ```json
  {
    "csrf_token": "aBcDe12345...",
    "message": "CSRF cookie đã được thiết lập."
  }
  ```

### 2.2. Đăng nhập
* **URL:** `POST /api/auth/login/`
* **Headers:** `Content-Type: application/json`, `X-CSRFToken: <token_đã_lấy>`
* **Body:**
  ```json
  {
    "username": "bep_truong",
    "password": "mat_khau_tai_khoan"
  }
  ```
* **Response `200 OK` (Thành công):**
  ```json
  {
    "message": "Đăng nhập thành công.",
    "user": {
      "id": 1,
      "username": "bep_truong",
      "role": "manager"
    },
    "csrf_token": "token_moi_sau_login..."
  }
  ```
* **Mã lỗi:**
  * `400 Bad Request`: Thiếu username hoặc password.
  * `401 Unauthorized`: Sai tên đăng nhập hoặc mật khẩu.
  * `403 Forbidden`: Tài khoản bị khóa (`is_active=False`) hoặc thiếu header CSRF token.
  * `405 Method Not Allowed`: Gọi bằng phương thức khác POST (ví dụ GET).

### 2.3. Lấy thông tin tài khoản hiện tại
* **URL:** `GET /api/auth/me/`
* **Response `200 OK`:**
  ```json
  {
    "id": 1,
    "username": "bep_truong",
    "role": "manager"
  }
  ```
* **Response `401 Unauthorized`:** Chưa đăng nhập hoặc session đã hết hạn.

### 2.4. Đăng xuất
* **URL:** `POST /api/auth/logout/`
* **Headers:** `X-CSRFToken: <token>`
* **Response `200 OK`:**
  ```json
  {
    "message": "Đăng xuất thành công."
  }
  ```

## 4. Hướng dẫn chi tiết cho TV3 & TV5 (Làm SF15 & SF17: Giao diện Đăng nhập & Danh mục)

### 4.1. Quy tắc gọi API từ React (Fetch với Session & CSRF)
Do backend dùng cookie session và CSRF middleware, mọi hàm `fetch()` ở frontend bắt buộc phải có:
1. `credentials: 'include'`: Để trình duyệt gửi cookie session và csrftoken.
2. Header `X-CSRFToken`: Đính kèm token khi thực hiện các method `POST`, `PATCH`, `DELETE`.

**Mẫu hàm helper gọi API đề xuất:**
```typescript
export async function apiFetch(url: string, options: RequestInit = {}) {
  // 1. Đảm bảo có cookie CSRF (lấy từ cookie hoặc gọi /api/auth/csrf/)
  const getCsrfFromCookie = () => {
    const match = document.cookie.match(/csrftoken=([^;]+)/);
    return match ? match[1] : '';
  };

  const headers = {
    'Content-Type': 'application/json',
    'X-CSRFToken': getCsrfFromCookie(),
    ...options.headers,
  };

  const response = await fetch(url, {
    ...options,
    headers,
    credentials: 'include', // BẮT BUỘC để gửi session cookie
  });

  // Nếu hết hạn session (401), chuyển hướng về màn hình đăng nhập
  if (response.status === 401 && !url.includes('/api/auth/login/')) {
    window.location.href = '/login';
    throw new Error('Phiên đăng nhập đã hết hạn');
  }

  return response;
}
```

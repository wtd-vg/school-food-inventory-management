## Lỗi cần sửa

P1: chặn luồng chính hoặc phá quy tắc dữ liệu. P2: validation, contract và độ phủ kiểm thử cần xử lý trước nghiệm thu.

### R01 — P1: Frontend chưa tích hợp session/CSRF

- Vị trí: `frontend/src/App.tsx`, `frontend/src/CategoryPage.tsx:29`, `:57`, `:102`.
- Mở UI với phiên mới: GET Category bị backend từ chối 401; UI chỉ báo lỗi kết nối, không có màn hình login.
- POST/PATCH chỉ gửi Content-Type, không lấy token và không có X-CSRFToken. Probe đã đăng nhập nhưng không gửi token nhận 403.
- Cần thêm login/logout/me, lấy CSRF trước login, dùng token mới sau login, xử lý 401 về login, ẩn thao tác ghi của viewer.
- Fetch cùng origin mặc định đã gửi cookie; nguyên nhân hiện tại không phải chỉ thiếu `credentials: 'include'`. Lỗi chính là chưa có luồng login và header CSRF.

### R02 — P1: Sai kiểu is_active vượt ràng buộc ngừng dùng Category

- Vị trí: `backend/apps/inventory/views.py:112`, `:135`, `:314`, `:459`.
- Category đang có FoodItem: PATCH `{"is_active":0}` trả 200 và lưu false, vì `0 is False` không khớp nhưng `bool(0)` là false.
- PATCH `{"is_active":"false"}` trả 200 và lưu true, trái ý nghĩa chuỗi người gọi có thể hiểu.
- Cần yêu cầu boolean JSON thật trước khi kiểm tra quan hệ hoặc lưu; áp dụng nhất quán cả POST và PATCH cho ba tài nguyên.

### R03 — P2: JSON đúng cú pháp nhưng sai cấu trúc làm API trả 500

- Vị trí: `backend/apps/inventory/auth_views.py:45–71`; các đoạn parse JSON trong `views.py`.
- Đã tái hiện POST login body `[]` → 500; login `{"username":123,"password":"x"}` → 500; POST categories body `[]` → 500.
- `json.loads` không đảm bảo kết quả là object. Sau parse, code gọi `.get()`/`.keys()` hoặc thao tác với giá trị sai kiểu.
- Cần kiểm tra object, username/password là string; trả 400 có lỗi theo field. Bổ sung các case null, array, số, bool cho mọi API ghi.

### R04 — P2: Thiếu kiểm tra độ dài và kiểu trước khi ghi DB

Cần chạy `docker compose up -d` rồi migrate để xác nhận; chưa có bằng chứng Docker chạy thành công sau sửa. Nếu host 5433 cũng bị chiếm, chọn cổng trống khác qua POSTGRES_HOST_PORT.

Log tiếp theo xác nhận db đã healthy tại host 5433, nhưng backend gặp `Bind for 0.0.0.0:8000 failed: port is already allocated`. Đã đổi mapping backend thành `${BACKEND_HOST_PORT:-8001}:8000`. Đồng thời sửa cấu hình R09 bằng environment `VITE_BACKEND_URL: http://backend:8000` cho frontend. Đã cập nhật README và `.env.example`; còn chờ chạy Compose/migrate và kiểm tra API qua frontend để nghiệm chứng runtime.
